# Model B 求解器为什么慢：实测排查

测试环境 `mg0828`，NVIDIA GH200 120GB，Julia 1.12.6，CUDA.jl 6.2.0，2026-07-26。
`solver/` 和 `references/` 均未修改，所有实验代码在本目录。

## 结论摘要

慢的原因不是一个，而是三个，按杠杆大小排列：

| 因素 | 现状 | 可得加速 |
|---|---|---|
| **1. 步长** `dt` 远小于精度需要 | `dt=0.002`（`run_randn`）/ `0.005`（`run.jl`） | **~10× / ~4×** |
| 2. kernel 每步搬运的数据量 | 每步 23 个数组 pass，其中 cuRAND 的 4 个 link 场占 45% | 1.7× |
| 3. 积分器 | SOSRA（3 次 stencil，显式） | 1.5× |

三者相乘，`run_hmc_10240` 形状下总计约 **26×**（按第 4b 节的 HMC 稳态检验定标；
第 3/5 节较宽松的条件方差指标给的是 44×）。

单步本身已经没有优化空间了——当前 kernel 跑在实测流式带宽的 96%，
`results.md` 里"慢来自计算量本身"这个判断方向对，但漏了关键一层：
**每步的 23 个数组 pass 里只有约 12 个是算法必需的，而步数比精度要求多了一个量级。**

---

## 1. 单步已经打满带宽（`bench_baseline.jl`）

先量一个 roofline 锚点：本机纯流式 copy kernel 实测 **2.69 TB/s**。

按"stencil 读命中 cache、其余每个 buffer 读写各算一次全数组 pass"建模，
当前实现每步搬 23 个数组 pass（cuRAND 写 4 + stage1 的 9 + stage2 的 7 + stage3 的 3）：

| L | Ne | 元素数 | ms/step | 模型 GB/s | 占实测峰值 |
|---:|---:|---:|---:|---:|---:|
| 128 | 512 | 8,388,608 | 0.2977 | 2592 | 0.96 |
| 256 | 128 | 8,388,608 | 0.2997 | 2575 | 0.96 |
| 64 | 2048 | 8,388,608 | 0.2948 | 2618 | 0.97 |
| 128 | 10240 | 167,772,160 | 7.9282 | 1947 | 0.72 |

即：**kernel 是纯访存受限的，且已经接近硬件上限。**
调 launch config、加 `-O3`、上 CUDA Graph、换 wrapper 都不会有收益
（这一点与 `results.md` 一致）。唯一能快的办法是**搬更少的数据**或**走更少的步**。

大数组只有 72%，是因为小数组时 L2（60 MB）替 stencil 和 link 场吃掉了一部分流量；
`Ne=10240` 时没有这个红利。顺带一个实测坑：若同一进程里还驻留着别的大 buffer，
`Ne=10240` 的步时会从 7.98 ms 劣化到 15.4 ms，测性能时要单独测。

## 2. 数据搬运：cuRAND 的 4 个 link 场是最大的单项（`bench_variants.jl`, `bench_noise.jl`）

当前每步 `Random.randn!(rng, links)` 生成一个 `(L,L,Ne,4)` 的高斯场，
stage1 再把它读回来（自己的 4 个 + 邻居的 4 个）。这一进一出就是 8 个数组 pass。
`Ne=10240` 下单是生成就要 **3.58 ms，占整步的 45%**（只跑到 750 GB/s，cuRAND 本身效率也不高）。

做了两件事：

**(A) 重组 stage 存储**。SOSRA 的更新对 `k1` 是线性的，把 `u` 的贡献在 stage1 就折进累加量：

```
h01 = u + dt*a21*k1 + b21*q
acc = u + dt*α1*k1  + amp*dW      -> u_final = acc + dt*α2*k2 + dt*α3*k3
pre = u + dt*a31*k1 + (b31+b32)*q -> h02     = pre + dt*a32*k2
```

于是 stage1 从写 4 个数组变成写 3 个，stage2 从读 5 个变成读 3 个，
buffer 从 8 个降到 3 个。**代数等价**：同一噪声下跑 200 步，与 `solver/` 逐点最大差
`9.5e-7`（rms φ=0.817），即 fp32 舍入量级。

**(B) 用 counter-based RNG（Philox4x32-10）在寄存器里现算 link 噪声**，
link 场完全不落显存。每个 site 算 3 次 Philox（自己 + x−1 + y−1 邻居），
把 `(wx,zx)` 和 `(wy,zy)` 各打包进一个 Box–Muller 对，全站只要 4 个 BM 对。

这里有个坑值得记：**瓶颈是 `log`/`sincos` 而不是 Philox 轮数**。
`Ne=10240` 下生成噪声散度的耗时：

| 方案 | ms |
|---|---:|
| cuRAND `randn!` 写 4 个 link 场 | 3.58 |
| inline Philox-10 | 3.56 |
| inline Philox-10 + `@fastmath` | **1.92** |
| inline Philox-7 + `@fastmath` | 1.53 |
| inline Philox-4 + `@fastmath` | 1.16 |

`@fastmath`（即 `__logf`/`__sinf`，2 ulp）几乎砍掉一半，降轮数收益反而小。保留 10 轮。

融进 stage1 后（寄存器 40→72）实际噪声成本只剩约 **0.69 ms**，比 cuRAND 便宜 5.2×。
把噪声拆成独立 kernel（变体 C，寄存器降到 32）反而更慢，因为多了 2 个数组 pass。

结果（`Ne=10240`，含噪声生成）：

| 变体 | ms/step | 相对 | buffer 数 |
|---|---:|---:|---:|
| `solver/ModelB_fixed` | 7.98 | 1.00 | 8 |
| A：仅重组 stage（仍用 cuRAND） | 7.59 | 1.05 | 7 |
| B：A + inline Philox | **4.74** | **1.68** | 3 |
| C：B 但噪声单独 kernel | 5.37 | 1.48 | 5 |

守恒性不受影响：变体 B 跑 2000 步后 `max|ΔM| = 5.0e-8`。

## 3. 步长才是最大的杠杆（`compare_integrators.jl`）

精度指标直接取项目真正要的量：**固定 φ₀ 下 p(φ(t=10)|φ₀) 的条件方差**
（把同一个 φ₀ 复制 Ne=4096 份，系综散布就是条件分布本身），
逐 k 模比较，基准是 SOSRA `dt=0.0005`。换种子重跑基准得到噪声底 **±0.038%**。

| 方案 | dt | Δvar/var |
|---|---:|---:|
| EM | 0.001 / 0.005 / 0.01 / 0.02 | +0.49% / +2.64% / +5.62% / +12.63% |
| SOSRA | 0.002 / 0.01 / 0.02 / 0.05 | −0.04% / −0.22% / −0.79% / −3.38% |
| ETD1 | 0.01 / 0.05 / 0.1 / 0.25 | +0.37% / +1.87% / +3.54% / +6.85% |
| ETDRK2 | 0.05 / 0.1 / 0.25 / 0.5 | −0.43% / −1.22% / −3.56% / −6.19% |

**SOSRA 在 `dt=0.02` 时误差只有 0.79%，而生产用的是 `dt=0.002`。**
也就是说当前步数比 1% 精度所需多了约 12 倍（`run.jl` 的 `dt=0.005` 多约 4.7 倍）。
这是目前最大的一项浪费，而且不需要动任何代码。

Euler–Maruyama 虽然每步便宜 3.5×，但误差随 dt 线性上升，等精度下反而比 SOSRA 贵 3.7×——
**不要为了省单步成本降阶。**

## 4. 指数积分器（ETD）：把线性刚性部分和噪声解析积掉（`modelb_etd.jl`）

Model B 的线性部分在 Fourier 空间是对角的：

```
λ_k = k̂²(2κk̂² + m0²)/γ,   k̂² = 4(sin²(kx/2)+sin²(ky/2))
φ_k <- e^{-λdt} φ_k + dt·g1(λdt)·N_k + sqrt(V_k)·ξ
V_k = (2T/γ) k̂² N dt·g2(λdt),  g1(x)=(1-e^{-x})/x, g2(x)=(1-e^{-2x})/(2x)
```

线性漂移和守恒噪声都是**精确**积分的，只有 φ³ 带 dt 误差。
每步 2 个 FFT（ETD1）或 4 个（ETDRK2，Cox–Matthews 预测–校正）。
cuFFT 很便宜：`L=128,Ne=512` 一次 R2C 0.051 ms、C2R 0.131 ms。

三项验证：

1. **Gaussian 极限精确**（`validate_etd_linear.jl`，κ=0.2, λ=0，此时 m0²>0 理论可解）：
   S(k) 与 `T/(m0²+2κk̂²)` 的平均偏差在 `dt=2.0`（比生产 dt 大 1000×）时仍为 **−0.005%**；
   同一测试下 SOSRA `dt=0.05` 有 −2.0% 偏差。
2. **非线性区与实空间格式收敛到同一极限**（`validate_etd_limit.jl`）：
   ETD1 `dt=0.002` 给 +0.069%，ETDRK2 `dt=0.01` 给 −0.021%，都在 ±0.038% 噪声底附近。
3. **零模严格守恒**：k=0 处 `k̂²=0` 使 E=1、噪声和非线性系数都为 0，
   20000 步后 `max|ΔM| = 0.000e+00`（实空间格式是 5e-8 的舍入漂移）。

### 踩到并修掉的一个坑：半谱的伪自由度会指数放大

把状态存成 R2C 半谱时，`kx=0` 和 `kx=L/2` 这两列同时存了 k 和 −k，
二者必须严格互为共轭。它们的**反对称分量对非线性项和噪声完全不可见**
（FFT 往返会把它对称化掉），每步只被乘上 `e^{-λdt}`。
而 κ=0.28 时 `m0²=-0.328<0`，`k̂²<0.586` 的长波模是**线性不稳定**的，
最快增长率 0.048。于是 fp32 舍入播下的种子按 `e^{0.046t}` 长大，
`t≈600` 时整个 run 爆掉——与 dt 无关（`dt=0.002~0.02` 都在 t≈650 爆）、
与噪声无关（T=0 也爆）、爆的就是 `(kx=0, ky=5)` 这一个模，
实测增长率与解析值 0.046 完全吻合（`diagnose_etd_*.jl` 是排查过程）。

修法是每步只更新 `2ky≤L` 的正则条目、把镜像条目写成其共轭
（自共轭的 4 个模强制取实），零额外开销。修完 `t=2000` 全部稳定：

| 方案 | dt=0.01 | dt=0.02 | dt=0.05 | dt=0.1 |
|---|---:|---:|---:|---:|
| SOSRA `<φ²>` @t=2000 | 1.903 | 1.879 | **NaN** | **NaN** |
| ETD1 | 1.870 | 1.886 | 1.851 | 1.800 |
| ETDRK2 | 1.879 | 1.902 | 1.882 | 1.849 |

SOSRA 在 `dt=0.05` 爆是显式格式的稳定极限 `2/λ_max = 2/33.2 = 0.06`，符合预期。
ETD 没有这个限制。**任何用半谱存状态的实现都必须做这个投影**，
否则在有序相（m0²<0）会静默地炸。

## 4b. κ=0.2705 HMC 初态的稳态检验（`validate_etd_hmc.jl`）

Model B 保持 `exp(-S)` 不变（每条轨迹各自守恒 M，而 HMC 系综本身已带 M 的平衡分布），
所以**把 HMC 平衡组态喂进去演化，任何观测量都不该动**。这是比第 3 节的条件方差
灵敏得多的检验（z 值能到 90），协议照抄 `checks/fixed_sciml_results.md`：
L=128 均匀抽 512 个组态、不减各自均值、4 次独立噪声重复、配对 z 检验。

t=5 的相对漂移 %（配对 z），最灵敏的三列：

| 方案 | dt | action | phi4 | mean\|dS/dφ\|² |
|---|---:|---:|---:|---:|
| SOSRA | 0.002 | −0.096% (−1.6) | −0.091% (−1.3) | −0.108% (−1.6) |
| SOSRA | 0.01 | −0.274% (−4.5) | −0.156% (−2.2) | −0.380% (−5.8) |
| SOSRA | 0.02 | −0.998% (−16.2) | −0.571% (−7.8) | −1.326% (−20.6) |
| **ETD1** | **0.002** | **+0.028% (+0.5)** | **+0.014% (+0.2)** | **+0.091% (+1.4)** |
| ETD1 | 0.01 | +0.774% (+12.6) | +0.680% (+9.2) | +1.056% (+16.2) |
| ETD1 | 0.05 | +4.236% (+69.7) | +3.678% (+50.5) | +5.731% (+88.8) |
| **ETDRK2** | **0.01** | **−0.102% (−1.7)** | **−0.089% (−1.2)** | **−0.133% (−2.1)** |
| ETDRK2 | 0.05 | −1.044% (−17.5) | −1.206% (−16.9) | −1.498% (−24.1) |
| ETDRK2 | 0.1 | −3.025% (−47.8) | −3.453% (−48.1) | −4.305% (−64.1) |

结论：

- **ETD 在 κ=0.2705 的 HMC 初态上是正确的**：ETD1 `dt=0.002` 和 ETDRK2 `dt=0.01`
  的所有 |z| ≤ 2.1，与 SOSRA `dt=0.002` 控制组同一水平（该控制组也复现了
  `fixed_sciml_results.md` 里的结果）。本检验对 action 的 1σ 灵敏度约 0.06%。
- 偏差是**不变测度的移动而不是漂移**：ETD1 `dt=0.05` 的 action 偏差在 t=5 和
  t=100 都是 +4.24%，早已饱和。
- 偏差集中在 UV 观测量（action、φ⁴、|dS/dφ|²），IR 的 `S(k_min)` 全部在噪声内
  （|z| ≤ 3.5）。这与"线性部分和噪声被精确积分、只有 φ³ 带 dt 误差"一致。
- 磁化：k 空间零模严格不变，回到实空间后 t=100 的 `max|ΔM| = 1.2e-7`，纯 fp32 舍入。

**这个检验修正了第 3 节的成本估计**。条件方差指标偏 IR、偏宽松；按 1% action
偏差重新定 dt（`L=128, Ne=10240`）：

| 方案 | 1% action 偏差所需 dt | ms / 单位 t | 相对现状 |
|---|---:|---:|---:|
| 现状：SOSRA @ dt=0.002 | — | 3990 | 1.0× |
| SOSRA（`solver/`）@ 0.020 | 0.020 | 399 | 10.0× |
| SOSRA 融合+inline @ 0.020 | 0.020 | 237 | 16.8× |
| ETD1 @ 0.013 | 0.013 | 316 | 12.6× |
| **ETDRK2 @ 0.049** | 0.049 | **156** | **25.6×** |

即 `10×`（步长）× `1.7×`（kernel）× `1.5×`（换 ETDRK2）≈ 26×，
比第 5 节按条件方差算的 44× 保守。**以这一版为准**——严的指标说了算。
ETD1 在这个指标下不划算（每步便宜但 dt 上不去），要换就换 ETDRK2。

## 4c. dt=0.002 下与 SOSRA 的正面对撞，以及由此找到的一个 Float32 bug

固定 dt=0.002（两种格式都近乎精确），从同一批 512 个 HMC 平衡组态出发演化到
t=2000，UV 和 IR 观测量全测。t=0 的 HMC 系综本身就是精确的静态基准。
脚本：`compare_sosra_etdrk2.jl`（三方对比 + 每格式两个噪声种子）、
`diagnose_etd_lowk.jl`（dt 扫描）。

### 症状

κ=0.28 一切正常，但 **κ=0.2705 下 ETD 在最低几个 k 模上明显偏离**，
而真正的 UV 观测量（action、dS2、lap2、band 4–8）在两个 κ 下都吻合到 ≤0.17%：

| 量 | SOSRA | ETDRK2 | SOSRA 换种子 |
|---|---:|---:|---:|
| S(k̂²=0.0048) 相对 HMC | −0.3% | **+18.8%** | ±1.1% |
| phi2 | −0.16% | +0.34% | ±0.05% |

同格式换噪声种子只差 0.05~1%，所以不是涨落；512 个 HMC 组态的
τ_int≈1.3（N_eff≈400），也不是样本自相关。

### 根因：`exp(-λ dt)` 在 Float32 里丢掉了速率

更新式原本写成 `uk ← exp(-λ dt)·uk`。κ=0.2705 时最慢的模 λ≈−6e-4，
dt=0.002 给 λdt≈−1.2e-6，于是 `exp(-λdt)` 落在 1.0 上方仅约 10 个 ulp
（Float32 在 1.0 附近间距 1.19e-7）。**(E−1) 的舍入误差因此高达 2.5%**，
等于把线性速率系统性改错 0.2~1.3%，方向由该模在 ulp 网格上的位置决定。

这些模在 κ_c 附近**线性不稳定**（裸增长率 1.2e-3，t=2000 内裸增长 e^4.79≈120×）
且弛豫时间约 8e4，t=2000 只走完弛豫的百分之几，非线性来不及把速率误差纠回来，
于是一路累积。κ=0.28 时同样有量化误差，但那里 S(k_min) 小、弛豫时间只有 1750，
非线性能重新平衡，所以看不出来。SOSRA 在实空间做加法更新，从不把小速率存成
"1+极小量"，因此没有这个问题。

诊断证据（`diagnose_etd_lowk.jl` + 纯 ulp 算术预测）：

- ETD1 与 ETDRK2 给出几乎相同的偏差（+19.19% vs +19.46%），排除非线性阶数与校正步；
- ulp 算术正确预言了四个壳中三个的**符号与量级**；
- 并预言 shell k̂²=0.0024 在 dt 0.002→0.008 时**符号翻转** −3.11%→+2.84%，
  实测 −2.79%→+3.02%，同向翻转。

### 修复与验证

```julia
uk ← uk + expm1(-λ dt) * uk        # 而不是 exp(-λ dt) * uk
```

`expm1` 以完整相对精度保住小量，加法的舍入是无偏的。CPU 上核算：速率误差从
0.2~1.3% 降到 1e-5%，t=2000 的预测偏差从 ±2~10% 降到 ±0.0001%。
同一轮还修了 `g2c(x)=(exp(−x)−1+x)/x²` 的三项相消（Float32 下 x≈1e-3 时相对
误差 24%），改用 `expm1` 加更宽的级数分支。

修复后同一测试（κ=0.2705，512 组态，t=2000，相对 HMC 精确基准；最低壳统计
误差约 4%，phi2 约 0.17%）：

| 方案 | phi2 | k̂²=0.0024 | k̂²=0.0048 | k̂²=0.0096 | k̂²=0.012 | band 1–2 | band 7–8 |
|---|---:|---:|---:|---:|---:|---:|---:|
| SOSRA dt=0.002 | −0.187% | −0.707% | +0.228% | +0.128% | −3.602% | −0.136% | −0.123% |
| ETD1 dt=0.002 | −0.088% | +0.253% | +0.144% | +0.227% | −1.166% | −0.270% | −0.002% |
| ETDRK2 dt=0.008 | −0.176% | +0.420% | +0.233% | −0.027% | −1.560% | −0.385% | −0.177% |
| ETDRK2 dt=0.002 | −0.040% | +0.373% | +0.369% | +0.602% | −0.756% | −0.314% | −0.268% |

`+19.2% → +0.14%`，IR 与 UV 全部落回统计散布内，**单一根因**。

修复后重跑前面四项验证，数字**逐位不变**（Gaussian 精确性 mean ±0.005~0.019%；
dt→0 极限 ETD1 dt=0.002 +0.0693%、ETDRK2 dt=0.01 −0.0204%；零模仍
`0.000e+00`；4b 的 t=5 稳态表 ETD1 dt=0.002 action +0.0282% vs 修复前
+0.0278%）。这正是问题所在——它们对这个 bug 完全无感，所以 4b、5 两节的
dt–精度标定和成本表不受影响，继续有效。

### 教训

1. **任何在 Float32 里做指数积分的实现都必须用 `expm1` 形式**，只要有 |λ|dt ≲ 1e-4
   的模。这类 bug 在 UV 观测量、短时间、远离临界点的测试里全部看不见——本目录
   前面四项验证（Gaussian 精确性、dt→0 极限、t=5 稳态、长时间稳定性）无一能发现它。
2. 能发现它的是：**临界点 + 慢模 + 长时间 + IR 观测量**，且必须有一个独立的精确
   基准（HMC 平衡系综）和一个校准误差棒的对照（同格式换种子）。
3. Gaussian 极限测试用 λ_φ4=0，**完全不检验非线性路径**；不要把它当成全面验证。

## 4d. 单组态逐点轨迹对比（`compare_pathwise.jl`）

统计一致不等于逐点正确。从**一个**指定的 L=128、κ=0.2705 HMC 组态（#5000）
出发跑 5000 步，逐点、逐模比。

**A：T=0 确定性。** 两者解同一个 ODE，差异只可能来自 drift 路径。
rms Δφ/rms φ = `8.4e-5`（dt=0.002）。IR 模吻合到 `1e-4`。
UV 波段显示的 15% 是 0/0 假象：确定性下 UV 按 `exp(-32.6 t)` 衰减，t=10 时
`|φ_k|=8.2e-4`，比 IR 的 `2.5e3` 低七个量级，已在舍入底（脚本同时打印 `|φ_k|`
就是为了让这一点无法被误读）。差异随 dt 减小而略增，是步数变多的舍入累积。

**B：T=1，两者 lockstep 推进、共用同一份守恒噪声增量 dW。**

| dt | rms Δφ/rms φ | UV band 7–8 相对差 | `sqrt(g2(λdt))` 偏离 1 |
|---:|---:|---:|---:|
| 0.002 | 3.92e-3 | 2.9e-2 | 2.8% |
| 0.001 | 1.96e-3 | 1.4e-2 | 1.4% |
| 0.0005 | 9.87e-4 | 7.8e-3 | 0.71% |

差异**有界**（100 步后饱和，不发散）且**严格正比于 dt**，即 dt→0 时两条轨迹
收敛到同一条。残余差异还能逐项对上：UV 模的相对差与 `sqrt(g2(λdt))` 相对 1 的
偏离逐个吻合，而那正是两种格式唯一合法的区别——ETD 用精确 OU 积分权重，
SOSRA 用 Euler 级裸增量（外加一个 ETD 没有的 Lévy 面积项 dZ，只进 stage 求值，
更高阶）。这一项上 ETD 才是更准的那个。

**方法上的一个坑**：两个格式必须**交错同步推进、共用同一个 links 数组**。
先后各跑完 5000 步、各自每步重新播种同一个 cuRAND 生成器，得不到相同的噪声场，
会假装出"完全去关联"的结论（本目录第一版脚本就踩了这个）。

## 5. 等精度成本对比（较宽松指标，见 4b 的修正）

单步实测（`bench_all.jl`）：

| 方案 | L=128,Ne=512 | L=256,Ne=128 | L=128,Ne=10240 |
|---|---:|---:|---:|
| SOSRA（`solver/`） | 0.306 | 0.307 | 7.98 |
| SOSRA 融合+inline 噪声 | 0.259 | 0.260 | 4.74 |
| EM inline | 0.124 | 0.123 | 2.26 |
| ETD1 | 0.217 | 0.228 | 4.05 |
| ETDRK2 | 0.405 | 0.431 | 7.56 |

把上面的精度表按幂律插值到"条件方差误差 1%"所需的 dt，得到每单位物理时间的成本
（`L=128, Ne=10240`，ms/单位 t）：

| 方案 | 1% 所需 dt（插值） | ms / 单位 t | 相对现状 |
|---|---:|---:|---:|
| **现状：SOSRA @ dt=0.002** | — | 3990 | 1.0× |
| SOSRA（`solver/`）@ 0.023 | 0.023 | 342 | 11.7× |
| SOSRA 融合+inline @ 0.023 | 0.023 | 203 | 19.7× |
| ETD1 @ 0.027 | 0.027 | 152 | 26× |
| **ETDRK2 @ 0.083** | 0.083 | **91** | **44×** |
| EM @ 0.0018 | 0.0018 | 1256 | 3.2× |

分解：`12×`（步长）× `1.7×`（kernel）× `2.2×`（积分器）≈ 44×。
**步长是主导项**，而且是唯一不用改代码就能拿到的。

在 `run.jl` 的小系综形状（`L=128, Ne=512`）下 FFT 的固定开销占比更大，
ETDRK2 相对现状是 12.5×（其中 4.7× 来自 dt=0.005→0.083，2.7× 来自换格式）。

## 6. `references/` 里可借鉴的

### `phi4lattice`（C++/CUDA）

- **每线程 RNG 状态、在 kernel 里现生成高斯数**（`tausworthe.h` 的 hybrid Tausworthe +
  `generateGaussian`，`randomizeAndDampKernel` 直接在动量更新里取噪声）。
  这正是上面 1.68× 的来源。我这里用的 Philox 是它的 counter-based 无状态版本，
  连 `taus_state` 数组都不用存，且可由 `(site, step)` 复现任意 site 的噪声——
  守恒噪声要取散度、必须读邻居 link，这个性质刚好用得上。
- 其 `stepMomentumConsKernel` 的 2D 守恒力 stencil 与本项目 drift 的
  `-Δ²φ + m²Δφ + gΔ(φ³)` 完全同构（含 `20φ0`、`8` 邻、`2` 对角、`1` 次近邻的系数），
  可以作为离散化的独立佐证。
- **但它不是同一个动力学**：它同时演化 φ 和共轭动量 π 做 leapfrog（二阶 Langevin），
  默认内部步长 0.00625。不能直接拿它的"每步一次 stencil"来对比本项目的一阶
  overdamped SOSRA 的"每步三次"。

### `chattopadhyay-modelB`（Julia/CUDA）

- **`launch_configuration` 定 launch 参数**：
  `kernel = @cuda launch=false f(...)`，再由 `launch_configuration(kernel.fun)` 取
  threads/blocks，并复用编译好的 kernel 对象。比现在硬编码的 `768/1024` 和
  `264` block cap 更可移植（换卡不用重调）。本机上实测差别不大（已经打满带宽），
  但换 GPU 时值得。
- 它是 3D `Float64` 上的 **Kawasaki pair-exchange Metropolis**（4 coloring × 3 方向
  = 12 个 kernel/sweep），不是 SDE 积分器。它标称的 `Δt=0.04` 是 MC sweep 的
  时间刻度，**不能**当作"本项目 SDE 可以用 0.04"的依据。
- 唯一算法层面可借的是：它用 `CUDA.CUFFT` 只是为了测 observable；
  而本项目的机会恰恰是把 FFT 用进积分器本身。

两个参考实现都没有做指数/半隐式积分——这是 Cahn–Hilliard 文献里的标准做法，
也是本次测出来收益最大的算法改动。

## 7. 建议的执行顺序

1. **先做 dt 扫描，不改任何代码。** 最灵敏、最省事的判据就是第 4b 节的
   HMC 稳态检验（`validate_etd_hmc.jl` 可直接换 κ 复用）：SOSRA 在 `dt=0.01`
   时 action 偏差 −0.27%、`dt=0.02` 时 −1.0%。你可接受多大偏差决定了能提到多少。
   还要在真正的下游量上确认（`dynamic_exponent/` 的 z 拟合、analysis 的关联函数、
   训练用的逐配置 target）——稳态检验只保证不变测度，不保证动力学时间尺度。
2. 若确认可以提 dt，收益立刻是 4~10×，零风险。
3. kernel 重写（融合 stage + inline Philox）是代数等价的，逐点差 1e-6，
   1.68×（大系综）/ 1.18×（小系综），可以放心上。
4. ETD 收益最大但改动最大，且换了噪声实现（不能逐轨迹对拍，只能统计对拍）。
   要换就换 ETDRK2（ETD1 在严指标下不划算）。上线前四项都要过：
   Gaussian 极限精确性、与 SOSRA 的 dt→0 极限一致、长时间稳定性（含半谱投影）、
   HMC 稳态检验。本目录的脚本可直接复用。
